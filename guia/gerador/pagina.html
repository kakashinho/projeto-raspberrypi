Entrar no Raspberry

O IP muda de rede para rede. O nome raspberrypi.local não muda.

1

Descubra o IP de hoje

ping raspberrypi.local -4
PowerShell do seu PCPS C:\> ping raspberrypi.local -4

Disparando raspberrypi.local [192.168.0.153] com 32 bytes de dados:
Resposta de 192.168.0.153: bytes=32 tempo=9ms TTL=64

O número entre colchetes é o IP. Hoje é 192.168.0.153. Amanhã pode ser outro, então refaça o ping.

O ping não achou o Raspberry?
  • Confira se o PC e o Raspberry estão no mesmo Wi-Fi ou no mesmo roteador. Rede de escola às vezes bloqueia: use o hotspot do celular nos dois.
  • No roteador: rode ipconfig, abra o “Gateway Padrão” (ex.: 192.168.0.1) no navegador e procure raspberrypi na lista de aparelhos.
  • No Raspberry, com teclado e monitor: hostname -I.
  • Tente direto pelo nome: ssh dsm@raspberrypi.local.
2

Entre com SSH

ssh dsm@192.168.0.153

Troque pelo IP do passo 1. Na primeira vez, digite yes. A senha (que não aparece ao digitar) quem passa é o responsável do grupo.

3

Crie a sua pasta e rode um teste

Dentro do Raspberrydsm@raspberrypi:~ $ cd codigos
dsm@raspberrypi:~/codigos $ mkdir -p task3 && cd task3          # troque 3 pelo número da sua tarefa
dsm@raspberrypi:~/codigos/task3 $ python3 ../rgb_pwm_interativo.py     # Ctrl+C para parar

Se o LED RGB da placa mudar de cor, está tudo certo.

  • Uma pasta por pessoa.
  • Ctrl+C ao terminar, senão o pino fica preso.
  • Fios só com o Pi desligado (sudo poweroff).
  • Tarefas 7 e 8 começam no PC e vão para o Pi depois.
Atalhos: VS Code, copiar arquivos, IP fixo
  • VS Code: extensão “Remote - SSH”, comando “Connect to Host”, dsm@IP. Você edita os arquivos direto no Pi.
  • Copiar arquivo do PC para o Pi: scp arquivo.py dsm@192.168.0.153:~/codigos/task3/
  • Parar de caçar IP: no roteador, reserve um IP fixo para o Raspberry (reserva de DHCP).

Rodar sem conflito

Dois programas só brigam quando usam o mesmo pino. Pinos diferentes convivem bem.

Se brigarem: o segundo programa costuma falhar com GPIO busy. Com RPi.GPIO pode nem avisar: os dois mexem no mesmo pino e o resultado fica estranho. Quase sempre é um programa esquecido rodando. Ache e pare (comandos abaixo).

Como rodar

1. Teste rápido, em primeiro plano

python3 teste.py

O terminal fica preso ao programa. Pare com Ctrl+C. É o jeito certo de testar a sua tarefa.

2. Deixar rodando e fechar o SSH

Programa que não pergunta nada

$ nohup python3 -u meu.py > meu.log 2>&1 &
$ tail -f meu.log      # ver os print() (Ctrl+C sai)
$ pkill -f meu.py      # parar

Programa que pergunta (input), como o calibracao_pot2.py

$ sudo apt install -y tmux   # uma vez
$ tmux new -s task3          # abre uma sala; rode lá
Ctrl+B, depois D             # sai deixando rodando
$ tmux attach -t task3       # volta à sala
$ tmux kill-session -t task3 # apaga e para o script

3. Sistema final: liga sozinho e reinicia se cair

Quando o main.py estiver pronto, ele roda como serviço do sistema. Só ele fica dono dos pinos. Os módulos (cancelas.py, presenca.py...) não rodam separados: o main.py os importa.

$ systemctl status estacionamento             # está rodando?
$ journalctl -u estacionamento -f             # ver os print() ao vivo (Ctrl+C sai)
$ sudo systemctl stop estacionamento          # parar para testar um módulo

O servidor Node é igual: copie o arquivo, troque o nome para estacionamento-web e o ExecStart por /usr/bin/node server.js (confira com which node). Se o DHT11 foi instalado num venv, use /home/dsm/venv/bin/python no lugar de /usr/bin/python3.

$ sudo systemctl stop estacionamento      # para o sistema final
  • Cada pessoa testa só os pinos da própria tarefa.
  • Antes de testar um módulo, pare o serviço do main.py.
  • Servidor Node: só um na porta 3000. EADDRINUSE quer dizer que já tem um rodando.
  • Deixou algo rodando? Avise o grupo, com o nome do script.

Cancelas

Dois servomotores: cancela de entrada (servo 1) e de saída (servo 2).

Ver na placa

{{PECA_servo}}

O servo gira até o ângulo que você mandar. A cancela é o braço dele. A largura de um pulso, repetido 50 vezes por segundo, define o ângulo.

{{FIG_servo_pwm}}
?Como o servo funciona por dentro (saiba mais)
Palavras novas
  • Pulso: um sinal que liga por um instante e desliga, como um toque rápido numa campainha.
  • Realimentação: olhar o resultado e corrigir, como girar o registro do chuveiro até a água ficar morna.
  • Corrente: a quantidade de eletricidade passando. Mede-se em ampères (A). 1 mA é um milésimo de ampère.

Em palavras simples

O servo é um motorzinho que sabe onde está. Você pede um ângulo, ele gira até chegar e para. Pense no chuveiro: você mexe no registro, sente a temperatura e corrige até ficar certo. O servo faz isso sozinho, muitas vezes por segundo.

O que acontece, passo a passo

  1. O Raspberry manda 50 pulsos por segundo no fio laranja. A largura de cada pulso é o pedido: pulso curto, ângulo pequeno; pulso longo, ângulo grande.
  2. Uma plaquinha dentro do servo lê esse pedido.
  3. Presa ao eixo existe uma peça (um potenciômetro, que você vai conhecer na tarefa 3) que informa o ângulo em que o eixo está de verdade.
  4. A plaquinha compara o pedido com o ângulo real. Se são diferentes, liga o motor para o lado certo.
  5. Quando ficam iguais, desliga o motor e segura a posição.
{{FIG_servo_malha}}
Quer ir mais fundo? Os detalhes técnicos
  • Largura vira ângulo. No nosso código, 0,5 ms é 0°, 1,5 ms é 90° e 2,5 ms é 180° (1 ms é um milésimo de segundo). São 2 ms para 180°, cerca de 11 µs por grau (1 µs é um milionésimo de segundo).
  • Engrenagens. Trocam velocidade por força: o motor gira rápido e fraco, e o eixo gira devagar e forte. É por isso que o servo consegue levantar uma cancela.
  • Por que treme. No Raspberry o pulso é gerado por software, e o sistema operacional atrasa alguns microssegundos de vez em quando. 30 µs de atraso são quase 3°. O código final gera o pulso por software (RPi.GPIO), então esse atraso pode aparecer. O pigpio geraria o pulso por hardware, sem esse atraso, mas o projeto final não o usa.
  • Por que o Pi reinicia. Parado, o servo gasta pouca corrente. Ao partir ou ao ser forçado, o motor puxa algumas centenas de mA (o SG90 chega perto de 650 mA travado). A fonte de 5 V do Pi cai e ele reinicia. Uma fonte externa resolve.

Sensor ultrassônico HC-SR04: tem um carro na frente da cancela?

Ver na placa

  • divisor de tensão
{{PECA_hcsr04}}

O sensor solta um som que a gente não ouve, espera o eco voltar e o tempo vira distância.

{{FIG_ultrassom}}
?Como o ultrassom mede distância (saiba mais)
Palavras novas
  • Eco: o som que bate num obstáculo e volta, como quando você grita numa montanha.
  • Ultrassom: um som agudo demais para a gente ouvir. Morcegos e golfinhos usam o mesmo truque.
  • Tensão: a “força” que empurra a eletricidade, como a pressão da água num cano. Mede-se em volts (V).

Em palavras simples

O sensor funciona como um morcego. Ele “grita” num som que não ouvimos, espera o eco voltar e mede quanto tempo demorou. Quanto mais longe o carro, mais demora o eco. Como a velocidade do som é conhecida, o tempo vira distância. É como gritar numa montanha e contar os segundos até ouvir a resposta.

O que acontece, passo a passo

  1. O Raspberry manda um pulso curtinho no pino TRIG: é o “pode falar”.
  2. O sensor solta uma rajada de som agudo.
  3. O som bate no carro e volta.
  4. Quando o eco chega, o sensor levanta o pino ECHO e o mantém levantado durante toda a viagem do som.
  5. O Raspberry cronometra por quanto tempo o ECHO ficou levantado. Esse tempo é a ida e a volta.
  6. Distância = tempo × velocidade do som ÷ 2. Dividimos por 2 porque o som foi e voltou.
Quer ir mais fundo? Os detalhes técnicos
  • Os dois “olhos”. São discos de cerâmica piezoelétrica: um material que vibra quando recebe eletricidade e gera eletricidade quando vibra. Um disco emite (uma rajada de 8 pulsos de 40 kHz, ou seja, 40 mil vibrações por segundo) e o outro escuta. O chip do módulo amplifica o eco, que é minúsculo.
  • Velocidade do som. No ar, cerca de 343 m/s a 20 °C (v ≈ 331 + 0,6 × temperatura em °C). Uma diferença de 10 °C muda a distância medida em uns 1,7%, ou menos de 0,1 cm a 5 cm.
  • Por que falha. Tecido e esponja absorvem o som. Superfícies inclinadas mandam o eco para o lado e ele não volta. O cone útil do sensor é de uns 15°, e objetos muito finos (menores que uns 9 mm) quase não refletem.
  • Por que o divisor de tensão. O ECHO sai com 5 V e o pino do Raspberry aguenta no máximo 3,3 V. Dois resistores iguais em série dividem a tensão ao meio, como dois trechos de cano que repartem a pressão: 5 × 330 ÷ (330 + 330) = 2,5 V.

Como o potenciômetro é lido (o Pi não tem entrada analógica)

?Como o potenciômetro e o botão funcionam por dentro (saiba mais)
Palavras novas
  • Resistência: o quanto um caminho dificulta a passagem da eletricidade, como um cano estreito. Mede-se em ohms (Ω); kΩ é mil ohms.
  • Capacitor: um pequeno “balde” que enche de eletricidade. Quanto mais estreita a torneira, mais devagar enche.
  • Entrada digital: um pino que só entende dois valores: 1 (ligado) ou 0 (desligado).
  • Pull-up: um resistor que “puxa” o pino para 1 quando nada está ligado a ele.

Em palavras simples

O potenciômetro é como o botão de volume do rádio: girando, você muda a dificuldade que a eletricidade encontra. O problema é que o Raspberry só entende ligado ou desligado, e não sabe medir isso direto. O truque é medir o tempo que o “balde” (o capacitor) demora para encher. Torneira bem aberta enche rápido, quase fechada demora: o tempo mostra a posição do botão.

O que acontece, passo a passo

  1. O código esvazia o capacitor (descarrega).
  2. O Raspberry liga o pino GPIO12 e começa o cronômetro. A eletricidade começa a encher o capacitor pelo resistor R2.
  3. O pino GPIO25 fica “olhando” a tensão. Quando ela passa de certo nível, ele passa a ler 1.
  4. O código para o cronômetro. Esse tempo depende da posição do potenciômetro.
  5. Na calibração você mostra os dois extremos (mínimo e máximo). Depois o código converte qualquer tempo em um número de 0 a 100.
Quer ir mais fundo? Os detalhes técnicos
  • Por dentro do potenciômetro. É uma trilha resistiva de 10 kΩ com um contato que desliza, o cursor. Entre as pontas a resistência é sempre 10 kΩ. Entre o cursor e uma ponta ela vai de 0 a 10 kΩ, conforme o ângulo.
  • O capacitor enchendo. A tensão sobe assim: V(t) = Vfonte × (1 − e^(−t ÷ RC)). Aqui R × C = 10 kΩ × 100 nF = 1 ms: em 1 ms o capacitor chega a 63% da tensão final.
  • Do tempo à posição. Os pinos do Pi decidem 1 quando a tensão passa de mais ou menos a metade de 3,3 V. Nesse limiar, t ≈ 0,69 × R × C. A posição do pot muda a resistência do caminho (e quanto da tensão chega ao pino de leitura, junto com um resistor interno de pull-down de dezenas de kΩ), então muda o tempo. Por isso é preciso calibrar: as peças reais variam de 5 a 20% do valor marcado.
  • Botão e pull-up. Uma entrada solta “flutua”: capta ruído e lê 0 e 1 ao acaso, como uma antena. O pull-up liga o pino a 3,3 V, então ele lê 1. Ao apertar, o botão liga o pino ao GND (zero). Como o resistor é grande, o GND vence e a entrada lê 0.
  • Bounce. Os contatos metálicos quicam por alguns milésimos de segundo ao fechar e geram várias leituras seguidas. O debounce ignora as repetições (por exemplo, bounce_time=0.05).

LED RGB: por que “nível baixo acende”

{{FIG_led_anodo}}
?Como o LED RGB e o buzzer funcionam por dentro (saiba mais)
Palavras novas
  • LED: uma lampadinha de estado sólido: acende quando passa eletricidade num sentido só.
  • Resistor: uma peça que limita a passagem de eletricidade para proteger as outras.
  • PWM: ligar e desligar muito rápido para controlar a intensidade, como piscar tão depressa que o olho vê só uma luz mais fraca.
  • Frequência: quantas vezes por segundo algo vibra. Mede-se em hertz (Hz).
  • Transistor: um interruptor que é fechado por eletricidade em vez de por um dedo.

Em palavras simples

O LED RGB tem três luzinhas dentro de uma só cápsula: vermelha, verde e azul. Misturando as três em intensidades diferentes saem todas as cores, como misturar tintas, só que de luz (o monitor e a TV fazem igual). O buzzer é um alto-falante minúsculo: ao receber um vai-e-vem rápido de eletricidade, a membrana vibra e faz som. Quanto mais rápido vibra, mais agudo é o som.

O que acontece, passo a passo

  1. LED. Cada cor tem seu pino. Nesta placa o LED é ligado ao 3,3 V pelo outro lado, então o pino em 0 acende e o pino em 1 apaga (como uma gangorra).
  2. Para uma cor mais fraca, o pino liga e desliga muito rápido (PWM). O olho não vê o piscar e percebe um brilho médio.
  3. Vermelho com verde dá amarelo. As três juntas dão branco.
  4. Buzzer. O pino do Raspberry é fraco demais para o buzzer. Ele fecha o interruptor eletrônico (o transistor), e o buzzer recebe energia dos 5 V.
  5. O código liga e desliga o pino numa frequência. O lá (A4) é 440 vezes por segundo. Cada oitava dobra a frequência (o A5 é 880 Hz).
Quer ir mais fundo? Os detalhes técnicos
  • Por dentro do LED. É uma junção de semicondutores: quando a corrente passa, elétrons e lacunas se recombinam e liberam a energia como luz. A energia define a cor: o vermelho começa a conduzir com uns 2 V, o verde e o azul com uns 3 V.
  • Por que o resistor. corrente = (3,3 V − queda do LED) ÷ 330 Ω. No vermelho: (3,3 − 2,0) ÷ 330 ≈ 4 mA. No azul e no verde: (3,3 − 3,1) ÷ 330 ≈ 0,6 mA, por isso brilham menos. Sem resistor a corrente não tem limite e o LED queima.
  • PWM. A proporção do tempo ligado se chama duty cycle. Ligado 50% do tempo parece metade do brilho. Aqui o pino liga e desliga umas 1000 vezes por segundo.
  • Buzzer passivo e ativo. O passivo é um disco piezoelétrico: toca a nota que você mandar. O ativo tem um oscilador dentro e só toca um tom fixo.
  • O transistor BC337. Uma corrente pequena na base, (3,3 − 0,7) ÷ 1 kΩ ≈ 2,6 mA, deixa passar uma corrente bem maior entre coletor e emissor (ganho de pelo menos 100, ou seja, até uns 260 mA). Os 0,7 V são a queda entre base e emissor.

O DHT11 manda temperatura e umidade por um único fio. Cada leitura leva cerca de 1 segundo.

{{FIG_dht_fluxo}}
?Como o DHT11 mede e conversa (saiba mais)
Palavras novas
  • Sensor digital: um sensor que já entrega o resultado em números, não em tensão.
  • Bit: a menor informação do computador: 0 ou 1.
  • Termistor: um resistor cuja resistência muda com a temperatura.

Em palavras simples

O DHT11 é um termômetro e um medidor de umidade dentro de uma caixinha, junto com um minicérebro. Ele mede sozinho e “conversa” com o Raspberry por um único fio, mandando os dois números. É como um colega que mede e te avisa o resultado batendo pancadinhas curtas e longas, um código combinado entre vocês.

O que acontece, passo a passo

  1. O Raspberry “bate na porta”: puxa o fio para baixo por uns 18 ms. É o pedido de medição.
  2. O sensor responde e manda 40 bits, um de cada vez.
  3. Cada bit é um pulso: curtinho (uns 27 µs) é 0, mais comprido (uns 70 µs) é 1.
  4. Os 40 bits formam 5 números: a umidade (2), a temperatura (2) e uma soma de conferência.
  5. O Raspberry confere a soma. Se não fecha, ele descarta a leitura e a biblioteca avisa com um erro (RuntimeError). Por isso a gente tenta de novo.
Quer ir mais fundo? Os detalhes técnicos
  • Temperatura. Um termistor do tipo NTC: a resistência cai quando esquenta. O chip mede a resistência e converte em °C.
  • Umidade. Um polímero que absorve vapor de água. Quanto mais água, menor a resistência elétrica entre dois eletrodos. O chip converte em % de umidade relativa.
  • Por que o Pi erra. O Linux não é um sistema de tempo real e pode atrasar a leitura alguns microssegundos, o que estraga um pulso de 27 µs. A soma de conferência não fecha e vem o erro.
  • Por que 2 segundos. O DHT11 é lento: precisa de cerca de 1 s por medição. Ler mais rápido só repete erros.

?Como pensar a lógica do sistema (saiba mais)
Palavras novas
  • Estado: a situação em que o sistema está agora: livre, abrindo, lotado...
  • Loop: um trecho do programa que se repete para sempre.
  • Polling: perguntar de tempos em tempos “mudou alguma coisa?”.

Em palavras simples

A lógica é o “porteiro automático”: um conjunto de regras do tipo “se isso, então aquilo”. Pense num semáforo, que passa por verde, amarelo e vermelho, e em cada fase decide o que fazer. O programa lembra em que estado está e, a cada volta, olha os sensores para decidir o próximo passo.

O que acontece, passo a passo

  1. A cada volta do loop, o programa olha o sensor: tem carro?
  2. Se o carro ficou 1 segundo na frente, o programa pergunta ao servidor se ainda há vaga.
  3. Com vaga: acende o LED amarelo, toca a música e abre a cancela.
  4. Espera o carro passar, depois mais 2 segundos, e fecha a cancela. Avisa o servidor: “entrou um carro”.
  5. Volta ao começo e fica esperando o próximo.
Quer ir mais fundo? Os detalhes técnicos
  • A pausa do loop. O sleep(0.2) faz o sistema olhar 5 vezes por segundo. Mais rápido gasta o processador à toa. Mais devagar pode perder um carro rápido.
  • Confirmar pelo tempo. Exigir 1 s de presença evita falsos avisos (ruído do sensor, um inseto na frente). É a mesma ideia do debounce do botão.
  • Polling. O main.py pergunta ao servidor “tem comando?” a cada volta. É simples e suficiente aqui. Em sistemas maiores o servidor “empurra” o aviso, o que se chama WebSocket.

{{FIG_banco}}
?Como funcionam o servidor e o banco (saiba mais)
Palavras novas
  • Servidor: um programa que fica esperando pedidos pela rede e responde.
  • API: a lista de pedidos que o servidor entende, como o cardápio de um restaurante.
  • Banco de dados: um arquivo organizado em tabelas onde os dados ficam guardados.
  • JSON: um jeito simples de escrever dados em texto, como {"tipo": "entrada"}.

Em palavras simples

O servidor é um atendente com um caderno. O Python chega e diz “entrou um carro”. O atendente anota no caderno, com data e hora. Depois o painel pergunta “quantos carros tem?”. O atendente conta as anotações e responde. O caderno é o banco de dados: guarda tudo, mesmo se o Raspberry for desligado.

O que acontece, passo a passo

  1. O Python faz um pedido POST /api/eventos com {"tipo": "entrada"}.
  2. O Node confere se o pedido está certo e escreve uma linha nova no banco, com a hora.
  3. O painel faz um pedido GET /api/resumo.
  4. O Node conta as linhas (entradas e saídas) e responde com um pacotinho de dados em JSON.
  5. O painel mostra os números na tela.
Quer ir mais fundo? Os detalhes técnicos
  • HTTP. O cliente manda um pedido (método, caminho e corpo) e o servidor devolve uma resposta (código e corpo). GET lê e POST cria. Códigos: 201 é “criado”, 400 é “pedido inválido”, 204 é “sem conteúdo”.
  • Express. Liga cada par (método, caminho) a uma função. app.post('/api/eventos', ...) diz “quando chegar um POST nesse caminho, rode isto”.
  • SQLite. Um banco que vive em um único arquivo, sem servidor separado. Ele grava em transações: se a energia cair no meio de uma gravação, o arquivo não fica corrompido.
  • Por que guardar cada evento. Com a hora de cada um dá para contar por dia, por semana ou por qualquer período, sem perder o histórico.

Palavras novas
  • Navegador: o programa que mostra páginas da internet (Chrome, Edge, Firefox).
  • JavaScript: a linguagem que roda dentro da página e a faz reagir.
  • DOM: a “árvore” de elementos da página (títulos, números, botões) que o JavaScript consegue mudar.

Em palavras simples

O painel é a vitrine do sistema: uma página web que mostra os números. Ela não sabe nada sozinha. A cada 2 segundos pergunta ao servidor “quantos carros?”, recebe a resposta e troca os números na tela, sem recarregar a página. É como olhar o placar de um jogo que se atualiza sozinho.

O que acontece, passo a passo

  1. O navegador pede a página ao servidor Node e mostra.
  2. O JavaScript da página liga um “despertador” que toca a cada 2 segundos.
  3. A cada toque, ele pede /api/resumo ao servidor.
  4. Quando a resposta chega, ele troca o texto dos números e redesenha o gráfico.
  5. Se o servidor não responde, a página mostra “sem conexão” em vez de travar.
Quer ir mais fundo? Os detalhes técnicos
  • Onde o código roda. O JavaScript da página roda no navegador de quem está olhando, não no Raspberry. O Raspberry só entrega os arquivos e os dados.
  • fetch e polling. fetch faz o pedido ao servidor. Repetir o pedido de tempos em tempos (polling) é a forma mais simples de manter a tela atualizada.
  • Gráfico. O Chart.js desenha dentro de um <canvas> a partir de listas de números, no caso as entradas e saídas de cada dia.
  • Tratar o erro. Rede e servidor falham de vez em quando. Uma página que avisa é melhor que uma tela travada.

O que cada área pede à API

  1. 3 contadores (vagas disponíveis agora, entradas e saídas): GET /api/resumo a cada 2 s. Vagas disponíveis = vagas − dentro.
  2. Gráfico da semana (Chart.js): o campo por_dia do mesmo resumo.
  3. Ambiente: GET /api/ambiente/ultima.
  4. Liberar saída: POST /api/comandos com {"alvo":"saida","acao":"abrir"}.

3. Ordem de montagem

  1. Etiqueta. Imprima a etiqueta Pimaco 6282 a 100% e teste antes em papel comum. Cole a A na borda de cima e a B (cortada na linha tracejada) embaixo. Fure só os círculos, de baixo para cima.

  3. Trilhas curtas de cada bloco: LED, DHT11, botão, buzzer, servos, potenciômetro e HC-SR04.
  4. Pontes das fileiras A e D até os pinos do J1, antes de soldar a barra 2 × 20.
  5. Barra 2 × 20 de pinos longos, com o corpo uns 3 mm afastado da placa, e depois os fios W1 a W4.
  6. Componentes (sugestão: dos mais baixos para os mais altos): resistores, C1, Q1, conectores, RV1, borne J7 e C2.

4. Testes antes de ligar

  • Com o jumper do JP1 fora, não pode haver continuidade entre o 5 V do Raspberry e o 5 V externo.
  • Nenhum curto entre qualquer 5 V e o GND, nem entre o 3V3 e o GND.
  • Com o multímetro em continuidade, confira as trilhas da etiqueta uma a uma.
  • Primeira ligação sem os módulos e com o jumper em RPi: meça 5 V no JP1 e 3,3 V no J5.
  • Com o jumper em EXT, ligue a fonte externa antes ou junto com o Pi. O − da fonte fica ligado ao GND da placa.

Como usar

Rodar o sistema no Raspberry

# No Raspberry (uma vez)
sudo apt update && sudo apt install -y python3-gpiozero python3-requests libgpiod2 nodejs npm
pip3 install gpiod

# No seu PC: copiar o sistema (troque pelo IP de hoje)
scp -r codigo/sistema dsm@192.168.0.153:~/codigos/final

# No Raspberry: instalar o servidor e ligar os serviços
cd ~/codigos/final && npm install
sudo cp estacionamento.service estacionamento-web.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now estacionamento-web estacionamento

# Painel, no navegador do PC ou do celular
http://raspberrypi.local:3000

Montar a placa

  • Lista de compras: docs/lista_de_materiais.csv
  • Etiqueta (imprimir a 100%): hardware/etiquetas_A_B_pimaco6282.pdf
  • Ordem de montagem e testes: seção “Replicar a placa” deste guia

Testar uma peça

# pare o sistema antes (veja “Rodar sem conflito”)
sudo systemctl stop estacionamento
python3 codigo/starter/tarefa2_teste_distancia.py

Gerar de novo este guia

python3 guia/gerador/montar.py
Guia gerado a partir do projeto da placa de interface (versão 2) e dos scripts da pasta ~/codigos.
